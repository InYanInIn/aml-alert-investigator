# ADR-0012: Secrets — .env locally, Key Vault with workload identity on AKS, OIDC in CI

Status: accepted · 2026-10-28

## Decision
- Local: git-ignored `.env`; `.env.example` lists names only.
- AKS: Key Vault secrets mounted by the Secrets Store CSI driver using workload identity.
- GitHub Actions: OIDC federation to Azure for ACR push and `helm upgrade`; no stored cloud credentials.
- No secret value is ever committed, logged or printed.

## Consequences
- More Terraform than a plain Kubernetes Secret, but no long-lived credentials exist anywhere.

## Amendment 2026-11-10 (M11)
- Decided for the AKS demo: workload identity (user-assigned identity, federated to the UI service account), Key Vault secrets through the AKS Key Vault Secrets Provider add-on, and a `workflow_dispatch` GitHub workflow that signs in with OIDC (federated credential scoped to this repository's `main` branch). No client secret anywhere.
- Postgres runs in the cluster (Flexible Server is unavailable on the Free Trial); its superuser password reaches the pod through the same Key Vault CSI mount, synced to a Kubernetes Secret.
- The database passwords are generated by Terraform and live in Key Vault and Terraform state; the state is local and destroyed with the demo.
- The spend guard no longer needs the `az` binary: it attests deployments through the ARM REST API with `DefaultAzureCredential`, so the pod needs the `Reader` role on the Azure OpenAI account in addition to `Cognitive Services OpenAI User`.
