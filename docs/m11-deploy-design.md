## What is deployed
- Separate Terraform root `infra/aks/` with its own state and resource group `rg-aml-demo`. The existing Azure OpenAI account is read as a data source only, so `terraform destroy` cannot delete it; the role assignments on it are the only resources created against it.
- AKS Free, one `Standard_B2s` node, OIDC issuer and workload identity on, Key Vault Secrets Provider add-on (CSI). 
- ACR Basic; the kubelet identity has AcrPull.
- PostgreSQL runs in the cluster (see Decision below): StatefulSet `postgres`, image `pgvector/pgvector:pg16`, 8Gi PVC on the default storage class, ClusterIP Service `postgres`.
- Key Vault (RBAC) with five secrets: `aml-postgres-password` (superuser password), `aml-owner-dsn`, `aml-mcp-dsn`, `aml-app-dsn`, `aml-evaluator-dsn`. Passwords are generated by Terraform (in state only).
- `id-aml-app`: federated credential for `system:serviceaccount:aml:aml-ui`; roles `Cognitive Services OpenAI User` and `Reader` on the existing OpenAI account (the Reader role is what the ARM attestation needs), `Key Vault Secrets User` on the vault.
- `id-aml-github`: federated credential for `repo:InYanInIn/aml-alert-investigator:ref:refs/heads/main`; roles `AcrPush` on the registry and `Azure Kubernetes Service Cluster Admin Role` on the cluster.
- The UI pod: one replica, `Recreate`, args `ui --no-browser --host 0.0.0.0`, service account annotated with the app identity client id, Key Vault secrets mounted by CSI and synced to the Kubernetes Secret `aml-ui` that feeds `AML_*_DSN`. Service is ClusterIP.

## Decision: in-cluster PostgreSQL
Flexible Server is unavailable (Facts), so Postgres runs as a StatefulSet in the `aml` namespace. The superuser password (`amladmin`) comes from Key Vault through the same CSI SecretProviderClass, synced to the Kubernetes Secret `aml-postgres` by `secretObjects`; it is an env var of the Postgres container. The UI pod waits for `pg_isready` on `postgres` in an init container. DSNs point at `postgres.aml.svc.cluster.local:5432`, database `aml_sim_ui`, `sslmode=disable` (traffic stays inside the cluster). Data lives only as long as the cluster: `terraform destroy` removes the disk with it, and there are no backups. One B2s node carries the app and Postgres; requests are 100m CPU and 256Mi for Postgres.

## Azure spend guard without the `az` binary
`verify_azure_deployments` now obtains an ARM token from `DefaultAzureCredential` (managed identity in the pod, `az login` locally) and reads the account and its deployments from `management.azure.com` (api-version 2024-10-01) with httpx. Unchanged: the same account name, kind, state, endpoint and sub-domain checks; the exact model, version, SKU, state, no spillover and default service tier per deployment; the 10 s timeout and 64 KiB response bound; refusal with a `409` before any request on any mismatch or error. Added: a missing `AML_AZURE_SUBSCRIPTION_ID`, a paged listing (`nextLink`) and non-object payloads also refuse. No redirects, no environment proxies.

## Data
`aml ui` creates the database, roles and schema itself, but its corpus copy needs a source database on the same server. `scripts/aks-load-db.sh <key-vault>` reads the four DSNs from Key Vault into environment variables (never an argument, never printed), opens `kubectl port-forward svc/postgres` on 127.0.0.1:15432 (closed on exit), and the DSN host and port are rewritten to the forward inside the script's process; then `scripts/load_aks_database.py` creates `aml_sim_ui`, migrates it, truncates the world schemas and copies every table of `core`, `truth`, `review`, `sim` and `corpus` from the local `aml_sim_ui` with binary `COPY` in foreign-key order, resets identity sequences, and compares row counts per table (the script fails if any differ). This carries the corpus with embeddings, the world, its thresholds (stored in `sim.*`) and the spend ledger. The script is repeatable and was verified against a scratch local database; it has not run against the in-cluster Postgres.

## Exposure
No public endpoint: the app has no login. ClusterIP only; demo through `kubectl -n aml port-forward svc/aml-ui 8765:8765`. Postgres has no public endpoint either; the laptop reaches it only through `kubectl port-forward`.
